## 반영한 변경

기존 질문 숫자 근거 제외 및 요청/실제 모델 불일치 차단을 유지했다. 새로 추가한 검사는 하나의 근거 구간에서 수치 관계가 뒷받침되는지, 명시한 인용 ID가 실제 구간을 가리키는지, 가구원수와 금액의 관계가 존재하는지를 보수적으로 검사한다. 문서 전체 숫자 집합을 섞어서 검증하지 않는다. 이는 모든 표·부정·조건의 의미를 증명하는 검증기가 아니다.

검색 개수 초과 방지, 첫 근거를 포함한 문자 예산 준수, 가구원수 보완검색에서 질문 연도·사업 유지, 자격·중복 질문의 예외 근거 우선 확보를 반영했다. 근거에 원문 SHA-256을 포함한다. 발행연도만으로 효력 종료를 추정하지 않으며 미확인 종료일을 '현재'라고 표시하지 않는다. 요청 연도와 문서의 적용시점을 구분하는 프롬프트를 적용했다. 근거 슬롯의 충족 여부는 키워드 기반 점검이므로 누락 여부의 완전한 증명으로 해석해서는 안 된다.

`welfare_evidence.py`는 근거 봉투·슬롯·구간별 검사를, `welfare_decision.py`는 선택적 판단 계약을, `welfare_telemetry.py`는 질문/답변 원문 없는 메모리 내 처리시간을 담당한다. 기존 검색·생성 경로를 대체하는 별도 대형 모델은 없다. UI의 답변 하단에 'v1.4.0.Beta 처리 내역'을 추가했다.

## 선택적 판단 설정

`beta-policy.json`의 기본값은 `decision_mode: OFF`이다.

| 모드 | 동작 |
|---|---|
| OFF | 추가 모델 판단 없이 규칙 개선 경로(A1) 사용 |
| SHADOW | 애매한 같은 범위의 후보만 관찰 평가, 최종 컨텍스트는 원본과 동일 |
| ACTIVE | 유효한 제안만 순서에 반영. 모든 근거 블록·ID·예외 원문 보존 |

`gemma_label`은 **미실측 실험 어댑터**다. 현재 적재된 모델 일치를 확인하고 해당 서버에서 A/B/C/Z와 선행 공백을 포함한 라벨의 단일 토큰화를 확인한다. 최대 1토큰 완성 요청은 한 번만 전송하며 재시작·재생성·다른 모델 로딩을 하지 않는다. 호환되지 않는 토크나이저/템플릿/응답, 시간초과, 후보·DB 해시 불일치는 규칙 경로로 복귀한다. 단일 토큰 결과의 품질·후보순서 편향은 실제 장비 시험이 필요하다. 상위 후보 상대점수나 정답 확률은 만들어내지 않는다.

`gemma_logits`는 설치 빌드에서 후보 전체 원시 점수 제공을 확인하지 못했으므로 미지원이다. `trained`는 학습·검수 데이터가 없어 구현하지 않았다. 외부 Jev/클라우드 연결, E2B→E4B 자동 전환, 추가 모델 다운로드는 넣지 않았다. 평상시 E2B 답변 생성 1회와 E4B 선택적 감독 후 최종 검증을 유지했다.

## 검증

`tools/validate_beta.py`는 원본의 임시 복사본(A0)과 Beta의 pytest를 실행하고, 원본 파일 SHA-256 전후 비교·구문 검사·결과 로그를 `quality/beta`에 기록한다. 원본 폴더에서 Python이나 pytest를 실행하지 않는다. 1차 A0는 95개 통과했고, Beta의 실패 3건 보완 및 회귀시험 추가 후 2026-09-20 최종 재검증에서 146개가 모두 통과했다. 실패·오류·건너뜀은 0개, 기존 라이브러리의 사용 중단 예정 API 경고는 2개다. 원본 검사 대상 156개 파일도 전후 일치했다. 최종 실행은 `--beta-only`이며 A0 결과는 이전 실행분을 보존했다.

```cmd
cd /d C:\Users\USER\Documents\Codex\seoguipowelfare-v1.4.0.Beta
C:\Users\USER\Documents\Codex\seoguipowelfare\deploy-current\.venv-openkb\Scripts\python.exe -X utf8 -B tools\validate_beta.py
```

결과 파일: `validation_summary.json`, `baseline.xml`, `beta.xml`, 각 `.log`, `original_hashes.json`. `--beta-only`는 이후 수정 회귀시험용이다. 최초 선택했던 `C:\Python314\python.exe`에는 pytest가 없어 기존 복지톡 가상환경의 Python을 읽기 사용했다. 패키지 설치·업데이트는 수행하지 않았다. 재검증 실행기는 이전 로그를 `quality/beta/runs`에 보존하고 설치된 패키지 버전과 시험 대상 파일 해시를 기록한다.

실제 GGUF 추론, 240문항 잠금 평가, 8GB/16GB 장비 비교, p50/p95·메모리 측정, 외부 통신 패킷 계측, 깨끗한 PC 설치·롤백·화면 E2E는 아직 수행하지 않았다. 소스 수정이나 합성 회귀시험을 이러한 측정으로 대신하지 않는다.

## 실행·포장

기존 실행 UI·원문 검색·타이머 경로를 보존했다. `welfare_launcher.py`와 웹·종료 스크립트는 Beta 포트를 사용한다. `build-exe.ps1`는 VERSION을 읽어 Beta 이름으로 패키징하며 `.spec`에 정책 파일을 포함했다. 새 EXE 또는 설치파일을 빌드한 상태는 아니다. 현재 Beta 폴더에는 models 폴더, llama-server.exe, wiki/kb-v120/welfare.db가 없으므로 이 폴더만으로 AI 답변을 실행할 수 없다. 패키징 환경 확인과 Beta 전용 실행 자산 구성이 남아 있다. 정식판 실행 파일을 Beta로 이름만 바꿔 사용하지 않는다.

## 한계·후속 작업

슬롯별 원문 소속과 원본 페이지의 정본 검수, 모든 표/각주의 완전한 관계 추출, 일반 부족 슬롯에 대한 확장 재검색, Host/Origin/인증 경계의 별도 검증, 모델/서버 바이너리 SHA 고정 벤치마크는 남아 있다. 현재 보완검색은 기존 가구원수·금액 경로를 보강한 범위이며 모든 질의 유형에서 보완검색을 구현했다고 주장하지 않는다. 모델 판단은 독립적 사실 검증이 아니며 OFF로 즉시 규칙 경로로 돌아갈 수 있다.
