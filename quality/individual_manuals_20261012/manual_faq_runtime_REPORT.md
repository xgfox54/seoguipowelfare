# 검수 매뉴얼 FAQ 적용 및 개선 평가

검수 완료된 원본 매뉴얼 FAQ 24건을 복지톡 로컬 DB에 추가하고 검색·답변 생성을 연결했습니다. 고정된 24문항의 최종 의미 검수는 **정답 23, 부분 1, 보류 0, 오답 0: 95.83%**입니다. 이전 기준선은 정답 9, 부분 6, 보류 5, 오답 4: 37.5%였습니다.

이 결과는 실행 DB에 넣은 FAQ와 같은 원문 사실을 사용하는 회귀 검사입니다. 독립 민원 정답률이나 복지톡 전체 정답률 95% 달성을 뜻하지 않습니다. Codex가 원문 및 의미를 검수했으며 사람의 최종 승인은 받지 않았습니다.

## 적용 내용

- 원본 PDF·변환 원문 해시, PDF 물리 페이지, 원문 행 범위를 기록한 검수 FAQ 보조 테이블을 추가했습니다. 평가용으로 고쳐 쓴 질문·필수 사실·채점 기준은 실행 자료에 넣지 않았습니다.
- 사업 별칭이 질문에 직접 나타나고 연도·지역·내용이 맞는 경우 검수 FAQ 전체 답변을 우선 검색합니다. 질문과 맞지 않는 사업·연도·제외 대상의 FAQ는 선택하지 않습니다.
- 검수 FAQ가 선택되면 생성과 근거 검증이 같은 FAQ를 사용합니다. 다른 사업의 일반 문단이 섞여 제한 조건이나 변경 방향을 뒤집는 문제를 줄였습니다.
- 날짜는 같은 인용 근거의 날짜 전체와 대조합니다. 24개월 이전 신청·이후 결정이라는 조건을 빠뜨리거나 결정 당월에 신청해야 한다고 만드는 문장을 검증합니다.
- 기간을 묻는 “얼마나”를 금액 질문으로, 이미 대상자인 사람에게 제공하는 서비스를 추가 대상 선정 질문으로 오인하던 슬롯 판정을 수정했습니다. 원문에 답이 있는 기간·예외를 없다고 경고하던 사례를 회귀 검사했습니다.
- 보험료를 “가구원 수에 합산하지 않는다”고 쓴 경우 같은 검수 FAQ가 해당 보험료를 합산하지 않는다고 명시할 때만 잘못 붙인 계산 대상을 제거합니다. 조건·부정 표현은 유지합니다.
- 답변 끝에 실제 원본 PDF 파일명·물리 페이지·원문 행을 표시합니다. 에너지바우처 하절기 FAQ에는 원본 각주의 긴급복지 연료비·연탄쿠폰 명칭도 반영했습니다.

검색 문서 적중은 상위 1개 기준 15→24건, 전체 검색 근거 기준 20→24건입니다. 기존 원문 FAQ 절 적중은 10건이었고 개선 후 해당 검수 FAQ 적중은 24건입니다. 기존 절과 새 FAQ 보조 근거는 표현 단위가 다릅니다. 검색 적중만으로 정답 판정하지 않고 필수 사실·조건·예외·날짜·단위와 모순된 추가 설명까지 대조했습니다.

### 실제 생성과 최종 재검증 구분

현재 Gemma 4 E2B QAT 모델로 24개 답변을 실제 생성했습니다. 마지막 계산 대상 보정 적용 전에는 엄격한 의미 검수 기준으로 **정답 22·부분 2 (91.67%)**입니다. 이후 모델·질문·DB를 바꾸지 않고 캡처한 24개 답변에 최종 결정적 검증을 다시 적용했습니다. 바뀐 답변은 `MFAQ-R1301a18cfbb` 한 건이며 나머지 23건은 동일합니다. 이를 최종 24건의 새 모델 생성으로 표기하지 않습니다.

- 원래 문구: “성인 자녀의 건강보험료는 가구원 수에 합산하지 않습니다.”
- 최종 문구: “성인 자녀의 건강보험료는 합산하지 않습니다.”
- 다자녀 인정과 소득심사 가구원 제외 조건을 그대로 유지했습니다. 근거는 모자보건사업 원본 PDF 445쪽, 변환 원문 14944–14946행입니다.

이 마지막 문항은 최종 코드로 모델부터 **새로 실행하여 정답을 확인**했습니다. 최초 시도는 모델 로딩 시간 초과로 중단됐고 전체 테스트 종료 후 재시도는 완료됐습니다. 원래 고정 문항과 질문·ID가 동일하며 새 답변은 최종 재검증 답변과 정확히 같습니다. 다자녀 인정·소득심사 가구원 제외·건강보험료 미합산 세 사실이 모두 충족되고 불필요한 보류 경고는 없습니다. 모델 생성 102토큰, 잘림 0이며 생성 요청이 실제 수행됐습니다. 별도 1문항 실행 파일의 SHA-256은 `7d53641f64d2cb03c999e77941a0cc2dedd793431ef700a430d3c0877545162a`입니다. 전체 고정 24문항 파일은 수정하지 않았습니다.

[최종 24개 의미 판정](manual_faq_runtime_semantic.json), [검증 전·후 답변과 실행 식별](manual_faq_runtime_revalidated.json)에 원문 필수 사실, 실제 답변, 판정 사유, 인용 근거와 해시를 기록했습니다. 재검증 도구는 캡처의 질문·정답셋 해시·DB 해시·FAQ 본문·출처 메타데이터가 그대로인지 확인한 뒤 적용합니다.

## 검증

- 실제 실패 재현: 5개 실패·2개 통과에서 시작하여 관련 회귀 검사를 통과했습니다. 날짜 조작·조건 누락·금액/기간 오분류·예외 누락을 다뤘습니다.
- 최종 전체 테스트: **409 passed, 1 warning**, 330.58초. 기존 Starlette/httpx 사용 중단 예고 경고 1건입니다.
- 새 모듈·새 테스트·재검증 도구 Ruff 검사: 통과. 수정한 기존 파일의 기존 Ruff 진단 16건은 HEAD와 코드·메시지가 동일하며 새 진단이 추가되지 않았습니다.
- `git diff --check`: 통과. LSP의 basedpyright·biome은 설치되어 있지 않아 LSP 검증은 수행하지 못했습니다.
- 임시 디버그 저널을 제거했습니다. 실행 로그는 현재 작업의 `work` 폴더에 보존합니다.
- 실제 1문항 재실행 도구가 띄운 Python·llama-server 프로세스는 종료됐음을 확인했습니다.

## 다음 개선 범위

우선 하절기 별도 금액처럼 검색된 근거의 필수 조건이 답변에서 빠지는 사례를 추가 검증합니다. 이후 이번 자료와 독립된 실제 민원 200문항을 다시 평가하여 FAQ 자료 확장의 효과와 복합 질문의 범위 손실을 확인해야 합니다. 기존 오답·부분 75문항 중 이번 원문 검수가 연결된 민원은 18개이며 **57개는 검수 완료 범위 밖**입니다. 추출 FAQ 1,173건 전체를 검수 완료하거나 실행 DB에 일괄 투입한 상태가 아닙니다.
