# e2e_v120.md

## 실행 경로

`welfare_launcher.py`(EXE의 실제 진입점)를 직접 실행해 포트 8765 기동을 확인했다.
`welfare_web.py` 단독 실행은 `shutdowner`가 배선되지 않아 초기 테스트에서 오해를
낳았고, 실제 앱과 동일한 launcher 경로로 재실행해 검증했다.

## 확인 항목

- 앱 실행 성공: launcher 기동 후 5초 내 포트 8765 LISTEN 확인
- Web UI 표시: `GET /` 200, `GET /api/status` 200 (문서 38, 섹션 18649, Gemma E4B/E2B available=true)
- 질문 전송/응답 생성 (3건, 모두 HTTP 200):
  1. "차가 있는데 생계급여 받을 수 있나?" - 100.0s, 자동차 재산 예외(장애인 사용 목적/생업용
     차량, 자동차말소등록증 제출 시 제외) 언급하는 근거 기반 답변
  2. "병원 갈 때 같이 가주는 서비스가 있어?" - 63.4s, 동행지원 서비스/병원동행 서비스를
     구분해 설명하는 근거 기반 답변
  3. "소득이 적은데 월세 지원 받을 수 있어?" - 40.4s, 주거급여 임차급여 기준(중위소득 48%
     이하)을 인용하는 근거 기반 답변
- 외부 인터넷/API 호출 없음: 실행 중 TCP 연결이 127.0.0.1:8765 LISTEN만 관측됨
- 검색 결과 -> Gemma context 전달: search -> fetch 분리 구조가 코드상 확인됨
  (`_load_hits_by_ids`가 검색 preview가 아닌 DB 원문 content를 다시 조회)
- 종료: `/api/shutdown` 호출로 uvicorn 서버 정상 종료(포트 리스너 소멸) 확인.
  이번 테스트 프로세스만 CommandLine으로 특정해 정리, DB lock 파일 없음.
